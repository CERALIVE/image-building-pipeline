# CeraLive first-party apt origin-pin manifest — Todo 29 (update-system-overhaul).
#
# Every Debian package name CeraLive publishes to apt.ceralive.tv, one per
# line (blank lines and `#` comments ignored). This is the SINGLE SOURCE both
# apt-preferences writers read to generate /etc/apt/preferences.d/ceralive-origin:
#   - mkosi/customize/apt-ceralive-repo.sh::install_apt_preferences()
#   - mkosi/mkosi.images/runtime/mkosi.postinst.chroot::setup_ceralive_repository()
#     (the dual-track twin the real ./build executor actually runs)
#
# For each name, both writers emit a PAIR of stanzas: our origin at 990 (below
# apt's "always" 1000, above the archive default 500 — so our build wins
# without silently downgrading an already-installed newer Debian candidate),
# and any same-name Debian package pinned to -1 (refused outright), so a
# same-name Debian/radxa build can never win a resolution against ours. This
# REPLACES the former blanket `Package: * / Pin: origin apt.ceralive.tv /
# Pin-Priority: 990` wildcard, which pinned every future apt.ceralive.tv
# publication sight-unseen — origin protection is now per exact name.
#
# The 15 legacy app-layer names (root AGENTS.md "Two operator-facing rosters"
# / package-layer.ts roster) plus the two platform-layer forks consumed via a
# URL+SHA pin swap (gstreamer-rockchip-fork, librga-fork — NOT REPOS entries,
# see root AGENTS.md) plus the fleet apt-credentials companion (Todo 11/29;
# see the FETCH/INSTALL wiring note in AGENTS.md for its current BLOCKED
# status — origin-pin readiness here does not imply it is fetched or
# installed yet).
